# 作品公開前チェックリスト

PVNMでエクスポートした作品データを公開する前に確認する項目です。まずは「配布する成果物が正しく動くか」を確認します。GitHub Releasesは公開先の一例として、使う場合だけ後半を見てください。

PVNM本体の公開準備は [PVNM本体公開前チェックリスト](pvnm-release-checklist.md) を見てください。

## 1. 公開する成果物を決める

- [ ] 公開したい対象を決めている。例: Windows、macOS、Web、Android。
- [ ] 対象に合うPVNMのエクスポート形式を選んでいる。
- [ ] 公開直前の作品データから、最終版のエクスポートを作り直している。
- [ ] 成果物名にバージョンや作品名を入れるか決めている。
- [ ] 古いエクスポート成果物と新しい成果物が混ざっていない。

## 2. エクスポート成果物の中身

| 形式 | 公開前に見るもの |
| --- | --- |
| `[PYXAPP]` | `.pyxapp` が生成されている。 |
| `[PYXAPP + ASSETS]` | `.pyxapp` と `<name>_assets/` を同じ階層で配れる状態になっている。 |
| `[macOS APP]` | `.app` が生成されている。配布する場合はzip化してから確認する。 |
| `[WINDOWS EXE]` | Windows用zipの中に、`.exe` と実行に必要なファイルが入っている。 |
| `[WEB HTML]` | `.html`、`<name>_assets/`、`pyxel/` が同じ階層関係で揃っている。 |
| `[ANDROID APK RELEASE]` | 署名済みAPKと `.sha256` が生成されている。 |

`[ANDROID PROJECT]` と `[ANDROID APK DEBUG]` は主に確認用です。一般配布には通常、署名済みの `[ANDROID APK RELEASE]` を使います。

## 3. 起動と通しプレイ

- [ ] 配布するzipやAPKを、公開時と同じ形で展開/インストールして起動できる。
- [ ] タイトル画面の画像とBGMが再生される。
- [ ] スタートからエンディングまで通しで進める。
- [ ] 背景、立ち絵、BGM、SEが想定通り。
- [ ] 選択肢と分岐が想定通り。
- [ ] 全エンディング到達後にEXTRASが開放される。
- [ ] CG GALLERYとEXTRA TEXTが表示できる。
- [ ] セーブ/ロードが動く。
- [ ] Windows向けならWindows実機、Android向けなら実機またはエミュレータなど、公開対象に近い環境で確認している。

## 4. 画像と音声

- [ ] 画像の色味がターゲット環境で許容できる。
- [ ] 画像、BGM、SEが成果物内で不足していない。
- [ ] 不要なオリジナル画像や制作途中ファイルを手で配布物に追加していない。
- [ ] BGM/SEの音量バランスがよい。
- [ ] Web/Androidで初回操作後に音声が再生される。

色味に違和感がある場合は、[色とツール](colors-and-tools.md) のVN Palette Toolと、実機での見え方を確認します。

## 5. 配布ファイル

- [ ] Windows/macOS/Webは、利用者がダウンロードする単位のzipを作っている。
- [ ] Web版は `.html`、`<name>_assets/`、`pyxel/` の階層を崩さずzip化している。
- [ ] Android版はRelease APKを配布対象にしている。
- [ ] `.sha256` を配る場合、対応する本体ファイルと同じ場所に置く。
- [ ] ファイル名が利用者に分かりやすい。例: `LastEmulator-windows-v1.0.0.zip`。
- [ ] PVNMが同梱する `PVNM_LICENSE.txt`、`PVNM_THIRD_PARTY_NOTICES.md`、`PVNM_EXPORT_LICENSE_README.txt` を配布物から削除していない。

## 6. 作品としての案内

- [ ] 作品名、バージョン、対応OS/環境を書いている。
- [ ] 起動方法を書いている。
- [ ] 操作方法やセーブ/ロードの説明を書いている。
- [ ] 利用規約、実況/配信可否、素材クレジットなど、作品として必要な案内を書いている。
- [ ] PVNM側のライセンス通知とは別に、作品本編の著作権表示や利用規約を用意している。
- [ ] 不具合報告や問い合わせ先を決めている。

作品紹介サイトを作る場合は、[作品紹介サイトの作り方](work-website.md) も参照してください。

## 7. GitHub Releasesを使う場合

GitHub Releasesは配布先の一例です。自分のWebサイト、Booth、itch.io、Google Driveなど別の場所で配る場合、この章は置き換えて考えてください。

- [ ] GitHubアカウントを持っている。
- [ ] 配布用リポジトリを作っている。
- [ ] 公開リポジトリにするか、限定公開のまま配布するか決めている。
- [ ] Releaseを作成できる権限がある。
- [ ] Releaseタグを `v1.0.0` のような利用者向けの名前にする。
- [ ] Releaseタイトルと説明に、作品名、バージョン、更新内容、動作環境を書く。
- [ ] Windows zip、macOS zip、Web zip、Android APKなど、配布するファイルをRelease Assetへアップロードする。
- [ ] `.sha256` を置く場合、対応する本体ファイルと同じReleaseに置く。
- [ ] WebサイトからRelease Assetへリンクする場合、リンク先が正しい。

`pvnm-windows-build-*` はWindows EXE確認用の一時タグです。正規配布のReleaseタグには、`v1.0.0` のような利用者に見せる名前を使います。

## 8. 最終確認

- [ ] 公開ページからダウンロードリンクへ辿れる。
- [ ] ダウンロードしたファイルを展開/インストールして起動できる。
- [ ] 公開するファイルと、説明文のファイル名/バージョンが一致している。
- [ ] 公開後に差し替えが必要な場合の手順を決めている。
- [ ] 署名鍵、token、private素材、制作途中ファイルを公開していない。

ここまで確認できたら、選んだ公開先で配布できます。
