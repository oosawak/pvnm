# PVNM本体を公開する流れ

PVNM本体をGitHubなどで公開するときの作業順です。最後の確認用チェックリストは [PVNM本体公開前チェックリスト](pvnm-release-checklist.md) を見てください。

## 全体像

PVNM本体の公開は、作品のエクスポート成果物を配る作業とは別です。公開する対象は、PVNMのソースコード、ドキュメント、必要ならPVNM本体の配布用成果物です。

おすすめの流れ:

1. 公開範囲を決める。
2. READMEとdocsを現行実装に合わせる。
3. MITライセンスとして公開する準備をする。
4. 公開してはいけないファイルが入っていないか確認する。
5. GitHubリポジトリをpublicにする。
6. 必要ならGitHub Releaseを作る。
7. 新規利用者としてセットアップ手順を通す。

## 1. 公開範囲を決める

まず、何を公開するかを決めます。

- [ ] PVNMのソースコードを公開する。
- [ ] docsを一緒に公開する。
- [ ] サンプルプロジェクトを入れるか決める。
- [ ] PVNM本体の実行用zipやビルド済み成果物をRelease Assetとして置くか決める。
- [ ] 制作中の作品データやprivate素材を含めない。

ソースコード公開だけでも、利用者はREADMEの手順でPVNMを起動できます。配布用zipやビルド済み成果物を置く場合は、Release Assetとして分けると案内しやすくなります。

## 2. READMEとdocsを整える

公開後に最初に読まれるのはREADMEです。READMEは入口として短く保ち、詳しい内容は `docs/` に分けます。

- [ ] READMEから初回セットアップへ辿れる。
- [ ] READMEから主要機能のページへ辿れる。
- [ ] 現行画面にない機能を案内していない。
- [ ] Windows/macOSで必要なものが分かる。
- [ ] エクスポート形式ごとの違いが分かる。
- [ ] 作品公開とPVNM本体公開の説明が混ざっていない。

確認用ページ:

- [初回セットアップ](setup.md)
- [エクスポート概要](export.md)
- [作品公開前チェックリスト](work-release-checklist.md)
- [PVNM本体公開前チェックリスト](pvnm-release-checklist.md)

## 3. MITライセンスの準備

PVNMはMITライセンスで公開します。リポジトリ直下の `LICENSE` にMIT License本文を置きます。

READMEや配布ページには、次の意味が伝わる文章を入れておくと分かりやすいです。

> PVNMはMITライセンスで公開しています。著作権表示とライセンス本文を残すことで、誰でも自由に利用、複製、改変、再配布、商用利用できます。PVNMを改変した版を自分のツールとして公開することも可能です。

確認すること:

- [ ] `LICENSE` がある。
- [ ] 第三者ライセンスをまとめた `THIRD_PARTY_NOTICES.md` がある。
- [ ] READMEからライセンスが分かる。
- [ ] 著作権表示の名前や年が正しい。
- [ ] 作品素材など、PVNM本体とは別ライセンスのものを混ぜていない。

## 4. 公開してはいけないものを除く

publicリポジトリにする前に、private情報が混ざっていないか確認します。

確認対象:

- 署名鍵
- token
- API key
- 個人用パス
- 制作途中の作品データ
- private素材
- 大きすぎる一時ファイル
- OSのメタデータファイル

確認コマンド例:

```bash
git status
git log --oneline -5
```

必要に応じて、`rg` で `token`、`password`、`secret`、個人名やローカルパスを検索します。

## 5. GitHubリポジトリを公開する

GitHubで公開する場合は、privateリポジトリをpublicに変更するか、公開用リポジトリへpushします。

privateからpublicへ変える場合:

- [ ] 最新のcommitがpush済み。
- [ ] `LICENSE`、README、docsが揃っている。
- [ ] private情報が入っていない。
- [ ] GitHubのリポジトリ設定でvisibilityをpublicに変更する。
- [ ] public表示でREADMEとdocsのリンクを開いて確認する。

公開用リポジトリを別に作る場合:

- [ ] 正規の公開元リポジトリ名を決める。
- [ ] `origin` の向き先を間違えていない。
- [ ] public側へpushするブランチを決める。
- [ ] private側とpublic側の役割をREADMEや運用メモで混同しない。

## 6. GitHub Releaseを作る

PVNM本体の節目を配布するときは、GitHub Releaseを作るとバージョンを案内しやすくなります。

Releaseに書く内容:

- バージョン
- 主な変更点
- 既知の制限
- 動作環境
- セットアップページへのリンク
- 必要ならビルド済み成果物

タグは `v1.0.0` のような利用者向けの名前にします。確認用の一時タグと正規配布タグは分けます。

## 7. 公開後の確認

公開したら、新規利用者として一度通します。

- [ ] publicページでREADMEが読める。
- [ ] READMEから [初回セットアップ](setup.md) へ進める。
- [ ] `requirements.txt` で依存パッケージを入れられる。
- [ ] `python3 main.py` または明示したPythonパスで起動できる。
- [ ] SETTINGS、PLAY、保存/読込など基本操作が動く。
- [ ] Release Assetを置いた場合、ダウンロードして展開できる。

公開後に問題が見つかった場合は、修正commitをpushし、必要なら新しいReleaseを作ります。
